# workflow

How the agent responds and recovers: output styles, response shape, and stepping back when stuck.

## User-invoked

- **[explore](./explore/SKILL.md)** — `/explore [topic]` turns the agent into a thinking partner: it reads the code, runs only what looks, draws plain-character diagrams and weighs options, but writes no code and no file (a file only on a separate yes for that one file). It stays on until you say "хватит" / "stop", then gives a three-to-five-line summary — decided, open, next step — and asks before starting that step. Borrowed from OpenSpec's explore, without the `openspec` CLI.
- **[scan](./scan/SKILL.md)** — `/scan <command> [folder]` looks at a whole project, changes nothing in it, and shows what it found on one HTML page in the OS temp directory: paths as tiles that open in Cursor, code coloured by kind, proof for every finding. `what-is-it` is the first look at a project you do not know (what it is, its parts, main paths, where things are, how to run it, surprises); `architecture` finds shallow modules, scattered knowledge, leaks and parts that cannot be tested through their interface, with before/after pictures; `unused` runs knip read-only (it stops when the packages are not installed), checks each finding once more with a search, and splits them into "safe to remove" and "check first"; `security` runs gitleaks (whole git history, secrets never shown in full), semgrep and the package audit, installing the first two on the machine on first run, adds the model's reading of rights checks, input, queries, uploads and webhooks, marks each tool finding real or likely false alarm, and sorts by severity; `performance` reads for code that looks slow and gives a first summary at once, and only when a suspicion needs numbers adds a measurement plan, which it runs on this machine after your yes, cleaning up after itself; `docs` uses `better-docs`' inventory (purpose, last change, stale, repeats, finished plans) and checks every path, command, setting, number and name in the documents against the code, without changing a document; `comments` finds comments that lie about the code, stale TODOs (with their age from `git blame`), code left commented out, and comments that only repeat the code. `/scan` alone looks at the project and suggests which scan fits; it never starts one on its own. `/scan pin <command>` makes a separate `/scan-<command>` shortcut, `/scan unpin <command>` removes it. The item you pick comes back as a ready `/explore` or `/how` command. Built like Impeccable's `/impeccable`; `architecture` is adapted from Matt Pocock's `improve-codebase-architecture` (MIT).
- **[how](./how/SKILL.md)** — `/how <part>` explains one part of the code in the chat, the way a senior engineer onboards a colleague: what it is, who uses it (what calls in, what it calls out to), how it works step by step with a plain-character diagram, where things live, gotchas — in the project's own words, every fact tied to a file. A small part it reads itself; a large one it splits between 2–4 `Explore` subagents and writes the answer from their reports. `/how to <task>` adds where the new thing should go: the place, an existing example of the same pattern, the files to touch in order, one alternative. Changes nothing. `scan what-is-it` hands its picked part over here.
- **[how-to](./how-to/SKILL.md)** — `/how-to <task>` is a two-line shortcut for `/how to <task>`; install it together with `how`.
- **[why](./why/SKILL.md)** — `/why <code or question>` finds what led to the shape of the code, in the chat. It climbs from cheap to expensive and stops once answered: git blame and history, PR bodies and review comments via `gh`, comments and written decisions; then the connected ticket tracker; then docs and chat; error tracking only for defensive code. Several outside sources go to parallel subagents. Every claim is marked found (cited), converging, guess (with its chain) or unknown (with what was searched); the code is never evidence of its own motive, and the user's own guess is checked, not confirmed. Ends with who could answer the gaps and, before a change, what to keep, what is free to change, what to avoid. Changes nothing anywhere.
- **[zoom-out](./zoom-out/SKILL.md)** — `/zoom-out [area]` when you are lost in the details: one level up from where the conversation is, a plain-character map of what calls the area and what it calls, one line per part, in the project's words. No subagents, no page; then back to work or `/how <part>`. Adapted from Matt Pocock's `zoom-out` (MIT), since removed from his repo.
- **[focus](./focus/SKILL.md)** — Shape output to be action-first and skimmable (ADHD-friendly). Toggle on with `/focus`, off with "stop focus mode".
- **[output-style](./output-style/SKILL.md)** — `/output-style ELI5` switches in one command, no picker; bare `/output-style` lists every style reachable from here (built-in, user, project, plugin) and asks. Brings back the standalone command Claude Code removed in v2.1.91.
- **[baby](./baby/SKILL.md)** — Say the last answer again in plain, non-technical words, then keep every reply that way. Works in the session you are already in, unlike the `Baby` output style.
- **[output-style-add](./output-style-add/SKILL.md)** — Turn a description into a real output style: brainstorm the role, tone and format, write `~/.claude/output-styles/<name>.md`, offer to switch to it.
- **[handoff](./handoff/SKILL.md)** — `/handoff <what the next session is for>` compacts the conversation into a handoff document for a fresh agent. It goes to the OS temp directory, not the workspace. It points at plans, commits and issues instead of copying them, redacts secrets and personal data, names the skills to call next, and marks what was not verified. The reply ends with the file path and one line to paste into the next session. `handoff-lpm` calls it, and the agent may reach for it on its own.
- **[handoff-lpm](./handoff-lpm/SKILL.md)** — `/handoff-lpm <what the next session is for>` does the whole move: it calls the `handoff` skill for the document, then opens a new tab in the lpm app with `lpm run --command claude --prompt ...`, which starts a fresh Claude session and sends it the one-line message that points at the document. Needs the lpm app running.
- **[update-plans](./update-plans/SKILL.md)** — `/update-plans <what changed>` for when you change your mind mid-work. It finds the superpowers spec and plan (`docs/superpowers/specs/`, `docs/superpowers/plans/`, or asks), finds every place the change makes wrong in both directions, and shows all edits at once — was → now, why — for one yes. Done `- [x]` steps keep their mark and get a new `- [ ] Rework: …` step after them. Only those two documents change: no code, no commit. With no argument it asks what changed; if the whole idea changed it recommends a fresh `brainstorming` instead of a patch. Borrowed from OpenSpec's update-change.
- **[verify](./verify/SKILL.md)** — `/verify [ticket | file]` checks that the code does what was promised. It finds the promise (the argument, the ticket key in the branch name, the branch's spec or plan files, or a list from the chat), splits it into items and asks you to confirm them. Then a fresh subagent proves each item: it runs the existing tests and the program, and writes any missing test in a temporary copy of the project (a detached git worktree with the uncommitted changes and linked dependencies), deleted afterwards. The project itself is never changed. The report is a table (proven / broken / not verified) with must / should / could fix findings and the text of each new test, ready to paste, with a failing one as where the fix starts. Report only: it never fixes and never says "ready" while something is not verified. Borrowed from OpenSpec's verify, which only reads the code; this one runs it.
- **[wtf](./wtf/SKILL.md)** — "That last message did not land: re-pitch it." The agent says it once more — goal, where we are, the point, what it needs from you — in ASD-STE100 Simplified Technical English and in your own names for things, then stops. One shot, and it keeps the technical words; `/baby` is the one that drops them and stays on.

## Model-invoked

- **[rethink](./rethink/SKILL.md)** — Step back and rethink systematically after 3+ failed attempts at any task.
